# Media Dock 3.0.3

Media Dock 3.0.3 is a compatibility test candidate focused on recovering YouTube media acquisition after a Google Video Server HTTP 403 response and reducing setup before the first download.

## YouTube compatibility recovery

- A YouTube media task that receives HTTP 403 during acquisition now clears its managed partial staging and retries exactly once with the `web_embedded` compatibility client.
- The retry keeps the selected Deliverable Recipe, quality ceiling, Authentication Profile reference, managed runtimes, destination, and safe delivery name.
- Non-YouTube failures and non-403 failures do not enter the compatibility retry.
- If the compatibility attempt also fails, the task still moves to **Needs Attention** with bounded, sanitized diagnostic evidence.

## Desktop delivery default

- New video work starts with the current operating system Desktop as its save location.
- Users can still select a different directory before creating the Media Task.
- Existing files are never silently overwritten.

## Failure recovery and guidance

- Terminal network failures now remove task-owned partial staging before the Media Task moves to **Needs Attention**; shutdown interruptions still preserve their recovery context.
- TLS EOF failures become the structured Problem `network.tls-interrupted` instead of a generic acquisition failure.
- A YouTube HTTP 403 that remains after the compatibility retry becomes `youtube.connectivity.blocked`.
- Task Center explains the likely network, proxy, security-software, runtime-update, and Authentication Profile recovery steps in Simplified Chinese and English, then lets the user return the Source to Workbench for a controlled retry.
- Media Tasks persist a secret-free acquisition summary: attempt count, standard or embedded connection, trigger code, and managed-staging cleanup result. These fields survive restart and are included in sanitized diagnostics without storing URLs, titles, paths, Cookies, or Authentication Profile identifiers.
- Source Inspection failures now explain that the site, network, or proxy may be unavailable and recommend a bounded retry instead of showing only a generic error.

## Validation status

- The original cross-platform YouTube 403 source completed on macOS after the compatibility retry and produced a verified 1080p MP4 with video and audio streams.
- Automated domain, IPC, preload, renderer, staging-cleanup, build, and lint checks pass on macOS.
- Windows behavior must be validated through the native Windows package workflow and a real Windows test machine before release.
- Test packages remain explicitly labeled **Unsigned Developer Preview**.
